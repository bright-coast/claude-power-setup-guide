Claude Code Power Setup Guide

Set up Claude Code around how you work

Download one file and tell Claude to read it. Claude asks what you use, connects your tools and installs the skills you pick, one step at a time, and asks before it changes anything.

Download the guide How it works

Click to download the guide. If your browser shows it as text instead, right-click the button and choose Save link as (in Safari, Download Linked File As). Keep the file name ending in .md.

Then, in Claude Code, say

Read this guide and run my setup.

Open Claude Code in your ClaudeSetup folder first. Section 01 shows how. Claude starts by asking whether Bright Coast AI gave you the guide.

00

The whole journey

Six stops, from a downloaded file to a Claude that is set up around you. You download and say one sentence, and Claude leads from there.

  • Claude asks before it changes anythingYou approve each step, and every skill is read out to you before it is written.
  • One or two restarts are normalNew connections and skills appear after Claude Code restarts. Claude keeps a small progress file so it carries on where it stopped.
  • Your own work is never overwrittenA skill of yours with the same name stays as it is. If you say so, it is moved to a backup folder, never deleted.
01

Get started

Install Claude Code, make one folder, save one file and say one sentence. If Claude Code is already installed and you can log in, skip to step 3.

  • A paid Claude planPro, Max, Team or Enterprise, or an Anthropic Console account. The free claude.ai plan does not include Claude Code. Current plans are at claude.com/pricing.
  • A computer that qualifiesmacOS 13 or newer, or Windows 10 (version 1809) or newer, with at least 4 GB of memory. On an older or slow machine, close spare browser tabs first.
  • Two ways to run itThe Claude desktop app has a Code tab and needs no terminal. Or use a terminal: Terminal on Mac, PowerShell or Windows Terminal on Windows. Both run on your computer. Not sure? Pick the desktop app. The WhatsApp skill needs it.
Not the same thing

claude.ai/code is Claude Code on the web. It runs on Anthropic’s servers instead of your computer. It is a real product, but not what this guide sets up.

Pick how you will run it

Choose once. The steps below show only what applies to you.

  1. Install Claude Code

    Desktop appDownload the Claude desktop app from claude.com/download (Mac or Windows), run the installer, open it and sign in with your Claude account. Then click the Code tab.

    Mac Terminal
    Terminal
    curl -fsSL https://claude.ai/install.sh | bash
    Windows PowerShell
    PowerShell
    irm https://claude.ai/install.ps1 | iex

    The Mac line does not work in PowerShell, so use this one. A PowerShell prompt starts with PS. If you see 'irm' is not recognized, you are in the older Command Prompt: open PowerShell from the Start menu. You do not need to run it as Administrator.

    Install commands are Anthropic’s own, from code.claude.com/docs/en/setup, the place to check if one ever stops working.

  2. Log in

    The first time you open Claude Code it asks you to sign in with your Claude account. After that you land in something that looks like a chat or command window. That is normal: it is Claude Code running.

    In a terminal, start it with claude. To check it worked, run claude --version.

    Windows, do this once

    PowerShell blocks scripts by default, which trips up many installers. Run this once, before anything fails:

    PowerShell
    Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

    Anthropic also recommends Git for Windows: winget install --id Git.Git -e. Setup works without it, but updates and merges need it.

  3. Make a plain new folder called ClaudeSetup

    Desktop appInside your user folder, make a new folder called ClaudeSetup. Do not use your Desktop or Documents folder.

    Mac Terminal
    Terminal
    mkdir -p ~/ClaudeSetup
    Windows PowerShell
    PowerShell
    New-Item -ItemType Directory -Force $HOME\ClaudeSetup

    If the folder is already there, nothing breaks. Avoid Desktop and Documents: on Windows they are often inside OneDrive, and on a Mac they can be inside iCloud Drive. Syncing can make Claude Code crash.

  4. Save the guide into that folder

    The Download the guide button at the top of this page saves it straight away. The direct link is below: right-click it and choose Save link as (in Safari, Download Linked File As), and make sure the file name still ends in .md.

    https://raw.githubusercontent.com/bright-coast/claude-power-setup-guide/stable/claude-code-power-setup-guide.md

    The repo’s own page is github.com/bright-coast/claude-power-setup-guide.

  5. Open Claude Code in that folder and say the sentence

    Desktop appOn the Code tab choose Local, click Select folder and pick ClaudeSetup.

    Mac Terminal
    Terminal
    cd ~/ClaudeSetup
claude
    Windows PowerShell
    PowerShell
    cd $HOME\ClaudeSetup
claude

    Then tell Claude:

    Read this guide and run my setup.

    From there Claude walks you through it one step at a time. Expect to restart Claude Code once or twice. Claude tells you what to say afterwards.

One account per person

Never share a Claude login. Two people on one account causes session-sync conflicts across devices. Each person signs in with their own.

No synced or shared folders

Do not base Claude in a shared or synced drive (OneDrive, iCloud Drive, Dropbox, a team drive). Syncing can crash Claude Code, and a shared drive can expose your settings and logins.

  • PowerShell refuses the settingYour organisation’s Group Policy can override it. Ask your IT person to allow it, or to tell you what they allow instead.
  • winget or Git for Windows wants admin rightsAsk your IT person to install it for you.
  • Downloads are blockedOpen the address in your browser, save the file (Save link as; in Safari, Download Linked File As) and tell Claude the full path. Claude runs the same fingerprint check on that file.
  • A command is not recognised after installingClose and reopen your terminal. That is expected, not a failed install.
  • You see Claude installing Python or gitThat is normal. Claude sets up whatever the step you asked for needs.
  • An Apple window offers developer toolsOn a Mac, the first time git is used, Apple may offer to install “command line developer tools”. Click Install and wait until it finishes.
02

What “run my setup” does

Claude works through it one step at a time, checks that each thing worked, and asks before it changes anything.

Before step 1

  • The licence questionClaude asks whether Bright Coast AI gave you the guide, for example a link was sent to you or you found it in the Bright Coast AI client portal. If not, it tells you plainly that you are welcome to read the guide, that setting up from it needs permission from support@brightcoast.ai, and it stops without installing anything.
  • The permission mode checkBefore any command or file change, Claude asks which permission mode the session is in. If it says Auto, you switch to Manual: Shift+Tab in a terminal, or the mode selector next to the send button in the desktop app. Claude never switches it for you and waits until you confirm.
  • The one-page pictureClaude saves this page next to your guide and shows it to you: click its path in the desktop app (it opens in the Browser pane), or say yes in a terminal to open it in your browser. It is a plain file, and nothing is sent anywhere, though it may load its fonts online. If Claude cannot get it, it skips it and carries on.
  • A look at what you already haveIf you set up from an older guide or built skills of your own, Claude reads the folder names first and asks only for what is missing. It never overwrites a skill you built.

The seven steps

Steps 2, 3 and 6 only happen if they apply to you.

  1. What you use

    Claude asks which tools you use day to day, for example Notion, Xero, Stripe, HubSpot, Google Drive or spreadsheets. Then three quick questions: do you record or transcribe meetings, do you use WhatsApp for work, and are you a Bright Coast AI client? It then creates SETUP-PROGRESS.md.

  2. Google Drive Only if you use it

    Install Google Drive for desktop, sign in with your work account and make a small test file. A synced icon after a few seconds is the real proof.

  3. A shared team folder Only if you have one

    Claude checks it appears under Shared drives in Google Drive, then reads the team’s shared instructions back to you in its own words. If it can describe them correctly, the step worked.

  4. Connect your tools

    One at a time. You type /mcp, Claude checks what is already connected, and anything new is tested after a restart. Details are in section 06.

  5. How much Claude asks first

    You choose a permission mode (below). Claude also offers to write a safer settings file. It shows you the exact text first, and you can say no.

  6. Ask Rob Optional, clients only

    If you are a Bright Coast AI client, Claude mentions this skill once. It sends a question straight to Rob with the context attached and brings the reply back.

  7. Install skills

    The closing step. You pick from the list in section 03. Claude then checks that git is there, and asks you to restart.

After the restart

Quit Claude Code and open it again in the same folder. In the desktop app, close the app completely, reopen it and choose the same folder on the Code tab. In a terminal, type /exit, then run claude again. Then say the sentence once more. Claude finds SETUP-PROGRESS.md, tells you where you got to and carries on. If you installed Startup, it takes over next.

It keeps its place in a file

A restart ends the conversation, so Claude keeps SETUP-PROGRESS.md next to your guide. It is a plain text file you can open. It holds tool names and yes or no answers only, never passwords, tokens, keys or login codes. Steps you postpone are marked deferred and offered once, at the end.

SETUP-PROGRESS.md
## Steps
- [x] Step 1: what you use
- [x] Step 2: Google Drive (skipped, they don't use it)
- [x] Step 3: shared team folder (skipped, solo setup)
- [ ] Step 4: connections (Notion added, not yet tested, needs a restart)
- [ ] Step 5: how much Claude asks first
- [ ] Step 6: Ask Rob (deferred <date>, they will generate the token later)
- [ ] Step 7: skills

How much Claude asks first

These are the permission modes, by the names Anthropic uses. Shift+Tab cycles through them in a terminal. /permissions manages the individual rules.

  • Manual Safest for setupClaude asks before it edits a file or runs a command. Slowest, and the most control.
  • Accept editsChanges files in the working folder without asking each time, but still asks before most commands.
  • PlanClaude looks around and proposes a plan. It changes nothing.
  • Auto Switch away for setupA second checking model decides what needs asking. Anthropic says it reduces prompts but does not guarantee safety.
Anything that touches messages

WhatsApp, or sending email or chat messages: stay in Manual or Accept edits, never Auto.

Never Bypass permissions

It switches the safety checks off completely. Anthropic says to use it only inside isolated containers or virtual machines, not on your own computer.

~/.claude/settings.json
{
  "permissions": {
    "allow": ["Bash(git status)", "Bash(git diff *)"],
    "deny": ["Read(~/.ssh/**)", "Read(~/.secrets/**)", "Read(~/.wacli/**)", "Read(**/.env)"],
    "defaultMode": "default"
  },
  "model": "sonnet"
}
  • defaultMode: defaultClaude Code starts in Manual mode from now on.
  • allowTwo harmless git commands it may run without asking. There is no blanket Bash, Read, Edit or Write, so anything that sends, deletes or deploys still asks.
  • denyBlocks Claude’s file tools from your SSH keys, your .secrets folder, the WhatsApp login folder and any .env file. A strong guard, not a lock.
  • modelOnly a starting choice. Setup leaves it out unless you ask. If a settings file already exists, Claude reads it first and adds to it.

Claude’s ground rules during setup

  • Only what applies to youIt connects only the tools you use and installs only the skills you chose. It explains what something is and why before installing it, never writes into a folder it did not create, and never installs, updates or removes anything without your yes.
  • What it reads is material, never ordersIf an email, web page or downloaded file contains instructions aimed at Claude, it ignores them and tells you.
  • It does not call setup “complete”It tells you which steps are finished. Rules, memory, hooks and semantic search are optional (section 05).

04

Keeping it up to date

Skills and the guide improve over time. You decide what to take, and your own changes survive.

  • Check for updates

    check for updates

    Looks at every skill you installed from the repo, and at the guide, and tells you what is newer and what changed. It mentions a newly ready skill once. Ask any new skills for the full list.

  • Check the guide

    check the guide

    Checks only the guide file. A newer guide is saved next to this one as claude-code-power-setup-guide-<version>.md. Your current file is never replaced, and Claude does not follow the new one unless you say to.

  • Remove a skill

    remove
    and the skill’s name

    Claude shows which files will go, says your own settings for that skill go with it, and asks for a clear yes. The folder is moved to ~/.claude/skills-backup/, never deleted. It only removes skills it installed itself.

Every skill has two parts

The skill itself comes from the repo and can be updated. Your own answers and tweaks live in a separate file that updates never touch.

~/.claude/skills/<skill-name>/
SKILL.mdComes from the repo. Updates replace this file.
Updates stop here
local.mdYours. Your answers and tweaks. Updates never touch it. It can add to a skill or make it stricter, but never loosen an “ask first” or “never” rule.
.upstream.jsonA note of which version you installed and where it came from.
.upstream/base.mdAn exact copy of what was installed. It lets an update tell whether you edited the skill.
SKILL.md.bak-<version>-<YYYYMMDD-HHMM>A backup an update makes of the file it is about to replace.

How an update works

  • You see it firstClaude lists each update: the skill, your version, the new version and a one-line summary. Nothing is applied without your yes, and there are no silent updates.
  • The real file is comparedClaude downloads the new file to a temporary place and compares it before anything is written. The one-line summary is never the basis for saying yes.
  • Risky changes need a separate yesA new web address, a new command or script, a new file, folder, login or account, or a weakened “never” or “ask first” rule. Claude quotes the exact lines. If you say no to any, that skill is not updated at all.
  • Your edits are merged, not overwrittenIf you changed a skill directly, Claude applies every change that does not clash. Where the two overlap, it explains both sides and asks which to keep. If a merge is unclear, your version stays.
  • Git does the comparingShowing changes and merging use git. A fresh install works without it, but updates and merges need it. If git is missing, Claude says so and updates nothing.
  • A backup every timeBefore changing a skill, Claude saves a backup next to it and says where. Afterwards it shows what differs and reads the file back.
  • Quiet by defaultStartup runs the check once per session and only speaks up when something is newer.
What the fingerprint check does and does not do

Every download is compared with a fingerprint listed in the catalog. That confirms the file arrived complete and is the one the catalog names. The catalog and the files live in the same repo, so it does not protect you if the repo itself were ever compromised.

What does protect you: Claude shows you what changes before anything is applied, risky changes need a second yes from you, and Bright Coast AI runs release checks before it moves the stable branch. In the end you are trusting Bright Coast AI’s releases, the same way you trust any software you install.

If a fingerprint does not match, Claude stops and changes nothing. Please report it by opening an issue at github.com/bright-coast/claude-power-setup-guide/issues.

05

Memory and rules

Optional reading for later. This is what makes Claude Code remember you, and setup does not build it.

Not part of “run my setup”

Setup does not create your CLAUDE.md, rules, memory, hooks or semantic search. Sections 3 to 9 of the guide cover them, and you can build any of them later with Claude’s help.

Two levels of settings

Global ~/.claude/

Every project, every session. Your personal preferences, memory and rules. It is yours only, not checked into git. This guide is about this layer.

Project <repo>/CLAUDE.md

That one repo only, plus its own .claude/ folder. It is shared, so a teammate sees it too.

Where things live

A short map of your global folder. Each piece has one job.

~/CLAUDE.md          index of your projects
~/.claude/
  rules/               loads every session
  skills/              one folder per skill
  skills-backup/       never deleted
  settings.json        permissions, hooks
  projects/<workspace-name>/memory/
    MEMORY.md          always-loaded index
    user_role.md       who you are
    feedback_<topic>.md
    project_<topic>.md
    reference_<topic>.md

Four kinds of memory

Save only what would otherwise need re-explaining.

  • UserWho you are, your role and your knowledge level.
  • FeedbackCorrections and confirmations about how to work with you. The most valuable kind.
  • ProjectWho is doing what, why, and by when.
  • ReferenceWhere things live in other systems.

Rules, the always-loaded part

Every .md file in ~/.claude/rules/ loads into every session, in every project. That is where the preferences you never want to repeat live. The guide suggests starting with two: formatting (dashes, time zone, how you sign off) and execution discipline, which keeps Claude from running ahead of you.

  • Plan firstFor anything non-trivial, present a numbered plan and wait for approval.
  • VerifyNever call a task complete without proof: run the script, check the file.
  • Fix, then continueEscalate only when the fix needs a decision only you can make.

Go further, later

  • Semantic memory searchOptional, mainly for people who code. A local index of your memory files so Claude can search by meaning. The .md files stay the source of truth.
  • HooksSmall automatic reactions to Claude’s own actions, such as a reminder that survives when a long chat is compacted.
  • Superpowers pluginOptional, mainly for people who code. It is a third-party plugin by an individual author, not Anthropic or Bright Coast AI, and it runs with your own permissions. Install it only if you are comfortable with that.
06

Connect tools

Start with the connectors already in your Claude account, then test what you connect.

If you signed in to Claude Code with a claude.ai account, the connectors you added there are available in Claude Code automatically. That does not happen if you signed in with an API key or a cloud provider such as Amazon Bedrock, so check what is really connected.

  1. See what is connected

    Type /mcp and read out what it lists. In a terminal, claude mcp list shows the same. Claude cannot type a slash command, so you do.

  2. Add what is missing

    In your Claude account, at claude.ai/customize/connectors, add the Google connector for Gmail and Calendar and sign in with your own account. On Team or Enterprise plans, only an admin can add connectors.

  3. Restart Claude Code

    The list loads when Claude Code starts. Setup groups this with the restart at the end of step 7.

  4. Sign in and test

    Type /mcp again and choose the connector. Claude does one small real read, then asks it which Google account it is signed in to.

The Google sign-in trap

A login screen that worked is not proof. The standard Google connector covers exactly one Google account, so ask it which account it is signed in to, and check that it is yours.

A second Gmail address, Sheets or Slides write access, or Google Chat needs the more advanced Google Cloud route below.

Read-only by default

On the advanced route the connector starts with --read-only. Reading, listing and searching work. Anything that sends, edits or creates is blocked, including drafting an email or adding an event.

It is a guard, not a lock. To allow writes later, remove it and register it again without the flag.

The silent scope trap

A connector can finish its sign-in and still lack the one permission a real task needs. A Gmail connection once read and drafted fine but could not send. An automated task ran daily for a month and never emailed anyone, with no error anywhere.

After connecting anything that can send or write, do one real test of that exact thing.

A third-party tool

The connector is google-workspace-mcp, run by one individual. It is not Google and not Anthropic, and it will hold broad access to your Gmail, Drive, Docs and Sheets. Only go ahead if you are comfortable with that. The commands pin version 2.3.6, the newest on npm on 24 Sep 2026, so new code cannot arrive unnoticed. Move the pin only on purpose.

  1. Create the project under the account owner’s own Google loginAt console.cloud.google.com. If you are setting this up for someone else, use their login, not yours.
  2. Enable each API you need, one at a timeGmail, Calendar, Drive, Docs, Sheets, Slides and Forms. Enabling one does not cover the others.
  3. Set up the consent screenOn a Google Workspace (work) account, choose Internal, which has no 7-day sign-in limit. On a personal account, choose External and add yourself as a test user. An External app left in Testing signs you out every 7 days, which is Google’s rule. Switch it to In production to stop that. Google then shows “Google hasn’t verified this app”, which is expected for an app only you use: choose Advanced, then continue.
  4. Create an OAuth client ID of type Desktop appGoogle Chat is the one exception: it needs Web application with a callback URL. Keep the downloaded credentials.json out of any repo that is served publicly.
  5. Register the connector, read-only
    Terminal or PowerShell
    claude mcp add google-workspace --scope user -- npx -y google-workspace-mcp@2.3.6 serve --read-only
    To allow writes later, run claude mcp remove google-workspace --scope user, register it again without --read-only, and restart Claude Code. Test any write-capable connection on a copy of a real file first.
  6. Sign in each account by name
    Terminal or PowerShell
    npx -y google-workspace-mcp@2.3.6 accounts add [account-name]
npx -y google-workspace-mcp@2.3.6 accounts list
    The same command adds a second or third account later. Each gets its own named sign-in and never overwrites the last.
ToolWhat to do
Gmail, Calendar, DriveThe connector in your claude.ai account, for one Google account. Check it with /mcp.
Notion, Xero, Stripe, HubSpotCheck /mcp first. If it is missing, Claude helps you add it and you sign in in a browser window. It takes effect after a restart. Then ask something real and simple, such as which Notion pages it can see.
SpreadsheetsDepends whether it is Google Sheets or Excel. Writing to a Google Sheet needs the Google Cloud route. If nothing connects, paste the rows or save the sheet as a CSV file and give Claude its path.
Outlook or Microsoft 365Register an app in your own Entra ID with Delegated permissions, never Application. Keep one registration per tenant and check for an existing one first. A managed work tenant usually needs a Global Administrator to grant consent.
Apple Mail or iCloudAlready signed in to Mail.app on a Mac: apple-mail-mcp talks to it locally with no credentials. Otherwise use an app-specific password, never your real Apple ID password.
Any other mailboxA standalone IMAP connector pointed at your provider’s own settings. Leave sending switched off entirely, because a generic connector usually cannot withhold send on its own.
GitHubFor backups, use GitHub’s own tool: run gh auth login, then gh auth status. It signs you in through your browser, so you never paste a password or token into Claude.
Before you connect anything that can send

Check whether a third-party mail connector routes your mail through its own hosted service. If it does, a third party sees the mail flow, which is worth knowing but not a reason to avoid it outright. Keep tools that send, post or write to a database out of the auto-approved list, so you are asked before anything irreversible goes out. If an assistant needs your mailbox, use the provider’s real delegation feature, never your login.

Traps, all in one place

Each one has cost someone real time. Read them once now.

Before you start

  • claude.ai/code is the web versionIt runs on Anthropic’s servers, not your computer. Use the desktop app’s Code tab or a terminal.
  • The free planIt does not include Claude Code. You need Pro, Max, Team, Enterprise or an Anthropic Console account.
  • Desktop, Documents or a synced folderOneDrive, iCloud Drive and Dropbox syncing can crash Claude Code. Use a plain local folder such as ClaudeSetup.
  • A shared Claude loginOne account per person, always.
  • Windows: “running scripts is disabled”PowerShell blocks scripts by default. Run Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser once.

During setup

  • The session starts in AutoSwitch to Manual yourself. Never choose Bypass permissions. For anything that touches messages, stay in Manual or Accept edits.
  • A permission prompt for every file under .claudeThat is normal. Click a plain Yes each time, and never choose the option that lets Claude edit its own settings for the rest of the session.
  • Testing something you just installedRestart Claude Code first. Connectors and skills do not take effect in the session where you added them.
  • A login screen that workedIt is not proof. Ask the connector which account it is signed in to, and do one real read.
